## Part 2: Collaboration Layer — Build Plan

## What We're Building

A real-time collaboration service for AppBoards. Free, no accounts, no payment.
2–3 people on a phone call, each working on variants with AI assistants, all seeing each other's
work in real time. No client-side DB. No CRDT library.

**Domain:** appboards.co (purchased, DNS pointed at dfn01)
**Open source template:** github.com/adamnfineco/appboards (public, MIT) — "basic mode"
**Service repo:** github.com/adamnfineco/appboards-web (private) — server + sync agent + viewer

---

## Stack

| Layer | Tech | Reason |
|---|---|---|
| Server | Go | Single binary, embeds viewer HTML, deploys easily |
| DB | Postgres (dfn01) | Already there, no new infra |
| Real-time | WebSockets (gorilla/websocket) | Simple, no CRDT needed — server assigns IDs |
| Sync agent | Go binary | Single executable, no runtime, AI-friendly local API |
| Viewer | Plain HTML/JS (embedded in binary) | Matches AppBoard aesthetic, no framework |
| Deployment | systemd + nginx on dfn01 | Additive only — new vhost, new service, new DB |

No SQLite on client. No ElectricSQL/Litestream. Postgres is the single source of truth.
WebSockets push state to browsers. Sync agent holds state in memory only.

## Postgres Schema

```sql
CREATE TABLE projects (
  key         TEXT PRIMARY KEY,           -- 'fox-river-41'
  status      TEXT NOT NULL DEFAULT 'active', -- 'active' | 'archived'
  created_at  TIMESTAMPTZ DEFAULT NOW(),
  last_active TIMESTAMPTZ DEFAULT NOW()   -- updated on any variant activity
);

CREATE TABLE variants (
  id          SERIAL PRIMARY KEY,
  project_key TEXT REFERENCES projects(key),
  variant_id  TEXT NOT NULL,              -- 'p1vA', 'p1vB'
  page_id     TEXT NOT NULL DEFAULT 'p1',
  label       TEXT,                       -- optional: "A — Dark palette"
  status      TEXT NOT NULL DEFAULT 'claimed', -- 'claimed' | 'ready'
  html        TEXT,                       -- null until synced, max 256KB enforced in API
  owner_token TEXT,                       -- session token of the sync agent that claimed it
  sort_order  INT NOT NULL DEFAULT 0,     -- reserved for future reordering
  claimed_at  TIMESTAMPTZ DEFAULT NOW(),
  updated_at  TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(project_key, variant_id)
);

CREATE TABLE variant_counters (
  project_key TEXT NOT NULL,
  page_id     TEXT NOT NULL,
  next_index  INT NOT NULL DEFAULT 0,     -- 0=A, 1=B, 25=Z, 26=AA
  PRIMARY KEY (project_key, page_id)
);
```

### Deli ticket assignment (atomic transaction)
1. `SELECT ... FOR UPDATE` on `variant_counters` for `(project_key, page_id)` (upsert if missing)
2. Read `next_index`, convert to spreadsheet letter (A→Z, AA→AZ…)
3. Increment `next_index`
4. Insert row into `variants` with `status='claimed'`, `owner_token` from request
5. Update `projects.last_active`
6. Return assigned `variant_id`

No collisions. Two AIs calling simultaneously get different letters.

### Session archival
- Cron or background goroutine: every hour, set `status='archived'` on projects where
  `last_active < NOW() - INTERVAL '24 hours'` AND `status = 'active'`
- Archived sessions stay in DB. Reactivate on any API hit for that key (set `status='active'`, update `last_active`)
- Abandoned placeholders: variants with `status='claimed'` and `updated_at < NOW() - INTERVAL '1 hour'` get deleted on the hourly sweep

## API Endpoints

All JSON. Project key = access control. No auth tokens. All inputs validated and sanitized.

### Rate limiting & abuse prevention
- `POST /api/projects`: 5 per IP per hour, max 20 active sessions per IP
- All other endpoints: 60 per IP per minute
- Enforced via in-memory token bucket per IP (no Redis needed at this scale)
- **Per-project caps:** max 26 variants per page, max 10 pages per project (260 variants ceiling)
- **Storage cap:** 10MB total HTML per project. Rejects PUT if exceeded.
- These limits are generous for real jams and hostile to freeloading.

### Projects
```
POST /api/projects
Body: {}
Response: { "key": "fox-river-41", "viewer_url": "https://appboards.co/fox-river-41" }
Creates project. Rate limited.

GET /api/projects/:key
Response: { "key": "fox-river-41", "status": "active", "variants": [...] }
Returns project + all current variants. Reactivates archived sessions.
```

### Variants
```
POST /api/projects/:key/variants/claim
Body: { "page_id": "p1", "label": "Dark palette" }  (both optional)
Headers: X-Owner-Token: <session-token>
Response: { "variant_id": "p1vJ", "filename": "p1vJ.html" }
Deli ticket. Broadcasts 'variant_claimed'. Label shown as "J — Dark palette".

PUT /api/projects/:key/variants/:variant_id
Headers: X-Owner-Token: <session-token>
Body: { "html": "<full html string>" }
Response: { "ok": true }
Max 256KB. Rejects if owner_token doesn't match (you can only update your own).
Sets status='ready'. Broadcasts 'variant_updated'.

DELETE /api/projects/:key/variants/:variant_id
Headers: X-Owner-Token: <session-token>
Response: { "ok": true }
Only owner can delete. Broadcasts 'variant_removed'.

PATCH /api/projects/:key/variants/:variant_id/label
Headers: X-Owner-Token: <session-token>
Body: { "label": "Dark palette" }
Response: { "ok": true }
Only owner can relabel. Broadcasts 'variant_label_updated'.

GET /api/projects/:key/export
Response: full single-file AppBoard HTML with all 'ready' variants inlined
Content-Disposition: attachment; filename="appboard-fox-river-41.html"
Compiles all variants back into a standalone AppBoard file. Full circle.
```

### WebSocket
```
GET /ws/:key
Upgrades to WebSocket. Server validates key exists.

Messages (server → client):
{ "type": "variant_claimed",  "variant_id": "p1vJ", "page_id": "p1", "label": "Dark palette", "is_mine": false }
{ "type": "variant_updated",  "variant_id": "p1vJ", "html": "..." }
{ "type": "variant_label_updated", "variant_id": "p1vJ", "label": "..." }
{ "type": "variant_removed",  "variant_id": "p1vJ" }
{ "type": "heartbeat" }   -- every 30s

The `is_mine` field: server checks if the WS connection's owner_token matches the variant's owner_token.
If yes → "yours". If no → "someone else's". No names, no identity.
```

### Viewer
```
GET /:key        → serves embedded viewer HTML (key injected via template)
GET /            → landing page with key entry field
```

## Sync Agent (Go binary — `appboard`)

### Owner token
Generated once per `appboard new` or `appboard join` — random 32-char hex string.
Stored in `.appboard`. Sent as `X-Owner-Token` header on all API calls.
This is what distinguishes "yours" from "someone else's" — no names needed.

### Config file (`.appboard` in project root)
```json
{
  "key": "fox-river-41",
  "server": "https://appboards.co",
  "owner_token": "a1b2c3d4...",
  "local_port": 7341
}
```

### Instructions for AI tooling (add to `LLMCONTEXT.md` in open source repo)
> If `.appboard` exists in the project root, a collaboration session is active.
> Claim a variant: `POST http://localhost:{local_port}/variants/claim`
> Optionally pass `{ "label": "Dark palette" }` in the body.
> Response gives you `variant_id` and `filename` — write your HTML there.
> The agent handles syncing to the server. Do not manually push.
> To delete a variant you own: `DELETE http://localhost:{local_port}/variants/{variant_id}`

### Local API (localhost only)
```
POST /variants/claim
Body: { "page_id": "p1", "label": "Dark palette" }  (both optional)
Response: { "variant_id": "p1vJ", "filename": "p1vJ.html" }
Proxies to hosted API with owner_token.

DELETE /variants/:variant_id
Response: { "ok": true }
Proxies to hosted API. Also deletes the local file.

GET /status
Response: { "key": "fox-river-41", "watching": "/abs/path", "variants_owned": ["p1vJ", "p1vK"] }
```

### File watcher
- Uses `fsnotify` — watches project folder for `*.html` files matching `p\d+v[A-Z]+\.html` pattern
- 500ms debounce per file (avoid partial-write syncs)
- On stable write: reads file, rejects if > 256KB, `PUT` to hosted API with owner_token
- Ignores `index.html`, `example.html` — only variant files
- On agent startup: compares local files against server state. Local wins — pushes any that differ.
- No images stored: all images must be remote URLs. No base64 inlining enforced by size limit.

### CLI commands
```
appboard new                → POST /api/projects → write .appboard → start agent → print key + viewer URL
appboard join <key>         → write .appboard with given key + new owner_token → start agent
appboard status             → show key, watching path, variants owned
appboard open               → open appboards.co/:key in default browser
appboard export             → GET /api/projects/:key/export → save to appboard-{key}.html locally
```

### Multi-Project on One Machine

Each project folder has its own `.appboard` file with its own key and port:
```
~/projects/app-a/.appboard   → key: fox-river-41, port: 7341
~/projects/app-b/.appboard   → key: blue-ocean-7,  port: 7342
~/projects/app-c/            → no .appboard (solo mode)
```

- Run `appboard join` in each folder — each gets its own agent process
- If port 7341 is taken, auto-increments to 7342, writes the actual port to `.appboard`
- AI reads `.appboard` from its working directory — always talks to the right agent
- No cross-contamination. Switch projects by switching directories.

### Export

- "Export" button in sidebar → `GET /api/projects/:key/export`
- Downloads `appboard-fox-river-41.html` — single standalone file
- Contains all "ready" variants compiled into the classic AppBoard format
- Opens in any browser. No server needed. Full circle.

### Security
- All variant HTML rendered in `<iframe sandbox="allow-scripts" srcdoc="...">` — no parent DOM access
- No `allow-same-origin` — variant cannot access the host page
- CSP headers on the viewer page
- Demo board variants are hardcoded, not from the database

## Binary Signing + Notarization

### macOS (required — prevents Gatekeeper warnings)

Build pipeline for darwin-arm64 and darwin-amd64:

```bash
# 1. Build
GOOS=darwin GOARCH=arm64 go build -o appboard-darwin-arm64 ./cmd/agent/
GOOS=darwin GOARCH=amd64 go build -o appboard-darwin-amd64 ./cmd/agent/

# 2. Sign with A Damn Fine Co developer identity
codesign --force --options runtime --sign "Developer ID Application: A Damn Fine Co (3YGSXDS222)" \
  --timestamp appboard-darwin-arm64
codesign --force --options runtime --sign "Developer ID Application: A Damn Fine Co (3YGSXDS222)" \
  --timestamp appboard-darwin-amd64

# 3. Zip for notarization
ditto -c -k --keepParent appboard-darwin-arm64 appboard-darwin-arm64.zip
ditto -c -k --keepParent appboard-darwin-amd64 appboard-darwin-amd64.zip

# 4. Notarize
xcrun notarytool submit appboard-darwin-arm64.zip --apple-id <email> --team-id 3YGSXDS222 --password <app-specific-password> --wait
xcrun notarytool submit appboard-darwin-amd64.zip --apple-id <email> --team-id 3YGSXDS222 --password <app-specific-password> --wait

# 5. Staple (only works on .app/.pkg/.dmg — for standalone binaries, notarization ticket is checked online)
# For CLI binaries, stapling isn't possible. Gatekeeper checks the notarization ticket online.
```

### Linux + Windows
```bash
GOOS=linux GOARCH=amd64 go build -o appboard-linux-amd64 ./cmd/agent/
GOOS=windows GOARCH=amd64 go build -o appboard-windows-amd64.exe ./cmd/agent/
```

## dfn01 Deployment (additive only — shared server)

### New Postgres DB
```sql
CREATE DATABASE appboards;
CREATE USER appboards WITH ENCRYPTED PASSWORD '...';
GRANT ALL PRIVILEGES ON DATABASE appboards TO appboards;
```

### Security hardening
- Postgres: `appboards` user can only access `appboards` database
- Binary runs as dedicated `appboards` system user (no shell, no sudo)
- Env file readable only by `appboards` user (`chmod 600`)
- API validates all inputs: key format, variant_id format, HTML size, rate limits
- No raw SQL interpolation — parameterized queries only
- WebSocket connections validated against existing project keys
- HTTPS enforced (HTTP → 301 redirect)

### Systemd service (`/etc/systemd/system/appboards.service`)
```ini
[Unit]
Description=AppBoards collaboration server
After=network.target postgresql.service

[Service]
ExecStart=/usr/local/bin/appboards-server
Restart=on-failure
RestartSec=5
User=appboards
EnvironmentFile=/etc/appboards/env
WorkingDirectory=/etc/appboards
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true

[Install]
WantedBy=multi-user.target
```

### Nginx vhost (`/etc/nginx/sites-available/appboards`)
```nginx
server {
    server_name appboards.co www.appboards.co;

    location /ws/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        client_max_body_size 512k;
    }

    listen 443 ssl;
    # certbot fills in SSL lines
}
server {
    listen 80;
    server_name appboards.co www.appboards.co;
    return 301 https://$host$request_uri;
}
```

TLS: `certbot --nginx -d appboards.co -d www.appboards.co`

## Key Design Decisions

- **The website IS the product.** No marketing page. appboards.co loads the viewer with a welcome overlay.
- **No auth, no accounts.** Project key = access. Rate limiting + caps prevent abuse.
- **Attribution without identity.** Owner token → "yours" vs "someone else's." No names, no colors.
- **Variants belong to their creator.** Only owner_token holder can update/delete. Others create new.
- **Abuse prevention:** 256KB per variant, 26 variants/page, 10 pages/project, 10MB total/project, 5 projects/IP/hour, 20 active sessions/IP.
- **No images stored.** All images must be remote URLs. Size limit catches base64 abuse.
- **Sessions never truly die.** Archive after 24h inactivity. Reactivate on any API hit. Permanent storage.
- **Abandoned placeholders auto-clean.** Claimed but not updated for 1 hour → deleted.
- **Export to single HTML.** Full circle — the session becomes a shareable artifact.
- **Variant naming: "A — label".** Always alpha-sorted. Label is optional.
- **Viewer is stateless.** All state in Postgres. Viewer fetches on load, WS pushes updates.
- **iframe sandbox (no allow-same-origin).** Variant HTML cannot access the host page. Safe.
- **dfn01 is additive only.** New DB, new binary, new systemd service, new nginx vhost. Hardened.
- **Local file wins on conflict.** Sync agent pushes local state on startup if it differs from server.
- **macOS binary signed + notarized** by A Damn Fine Co (3YGSXDS222). No Gatekeeper warnings.
- **Multi-project:** .appboard per folder, agents per folder, auto-increment ports. No cross-contamination.
- **AI needs zero manual setup.** Reads LLMCONTEXT.md + .appboard. No MCP, no plugin, no config.
